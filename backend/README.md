# EduTechEx backend

Node.js API for the SAT practice app. Registrations are stored in MongoDB.

## Start

From this folder, run `npm install` and make sure `.env` contains `MONGO_URI` set to your MongoDB connection string, Brevo SMTP credentials (`BREVO_SMTP_HOST`, `BREVO_SMTP_PORT`, `BREVO_SMTP_USER`, and `BREVO_SMTP_KEY`), and `EMAIL_FROM` set to a sender address verified in Brevo (for example, `EduTechEx <no-reply@yourdomain.com>`). Registration notifications go to `adityacv@edutechex.com` by default; set `ADMIN_EMAIL` to use a different recipient. Then run `npm start`. The API listens on port 5000 by default; set `PORT` to change it. The server waits for MongoDB before accepting requests.

For SAT subscription checkout, add these values to `backend/.env` (never put the secret in the frontend):

```env
RAZORPAY_KEY_ID=rzp_test_your_key_id
RAZORPAY_KEY_SECRET=your_key_secret
SAT_SUBSCRIPTION_AMOUNT_PAISE=99900
SAT_SUBSCRIPTION_TAX_PERCENT=2
SAT_SUBSCRIPTION_DURATION_DAYS=365
SAT_SUBSCRIPTION_CURRENCY=INR
```

`SAT_SUBSCRIPTION_AMOUNT_PAISE` is the base price for one three-paper pack before tax. The checkout total adds `SAT_SUBSCRIPTION_TAX_PERCENT`; amounts are expressed in paise for INR. Each verified pack unlocks its three selected mocks for `SAT_SUBSCRIPTION_DURATION_DAYS` (the current default is one year). Keep `.env` out of source control. Use Razorpay test credentials until the flow has been verified in test mode.

## Routes

- `GET /api/health` reports whether the API is running.
- `POST /api/sat/registrations` accepts `{ "name", "email", "phone", "curriculum" }` and returns a registration ID.
- `POST /api/sat/registrations/:id/verify` accepts `{ "code": "123456" }` and verifies the one-time code emailed during registration.
- A verified registration or login returns a signed SAT session token. Send it as `Authorization: Bearer <token>` for subscription and mock-test API requests.
- `GET /api/pay/subscription` returns the signed-in student's full-library status and purchased mock-paper entitlements.
- `GET /api/pay/pricing` returns the configured base price, tax, and checkout total.
- `POST /api/pay/create-order` requires the signed-in student's token and one valid three-paper pack in `{ "testIds": ["04", "05", "06"] }`. The amount and duration are read from backend environment variables; clients cannot set the price or account.
- `POST /api/pay/verify-payment` accepts `{ "razorpay_order_id", "razorpay_payment_id", "razorpay_signature" }` and requires the same student's token. The backend verifies the checkout HMAC, confirms capture with Razorpay, and marks only that student's subscription paid.
- `POST /api/pay/webhook` accepts Razorpay `payment.captured` events and validates them using the raw request body and `RAZORPAY_WEBHOOK_SECRET`.

In the Razorpay Dashboard, configure a webhook to `https://<your-backend-host>/api/pay/webhook`, select the `payment.captured` event, and use the same webhook secret stored in `RAZORPAY_WEBHOOK_SECRET`. Restart the backend after changing `.env`.

The SAT registration and verification screens call these routes. OTPs are generated by the backend, expire after 10 minutes, and allow up to five attempts. Only a keyed hash of the code is stored in MongoDB. Brevo SMTP must be configured for registration to send email.

## Google Calendar counselling appointments

The backend runs on port `5000` by default (`PORT` overrides it). Add these values to `backend/.env`; keep the client secret and token encryption key on the backend only:

```env
GOOGLE_CLIENT_ID=your-oauth-client-id
GOOGLE_CLIENT_SECRET=your-oauth-client-secret
GOOGLE_REDIRECT_PATH=/api/calendar/oauth/call
GOOGLE_CALENDAR_ID=primary
BOOKING_TIME_ZONE=Asia/Kolkata
GOOGLE_MEET_ENABLED=true
FRONTEND_URL=http://localhost:3000
BACKEND_URL=
GOOGLE_TOKEN_ENCRYPTION_KEY=64_hex_characters_for_a_random_32_byte_key
GOOGLE_CONNECT_EMAIL=developers.doc@edutechex.com
ADMIN_COUNSELOR_EMAIL=adityacv@edutechex.com
SUPER_ADMIN_EMAILS=adityacv@edutechex.com
```

The OAuth service constructs one redirect URI from `BACKEND_URL` (or `http://localhost:${PORT || 5000}`) plus `GOOGLE_REDIRECT_PATH`. For the local defaults this is `http://localhost:5000/api/calendar/oauth/call`. In production set `BACKEND_URL=https://your-backend.onrender.com`; the resulting URI is `https://your-backend.onrender.com/api/calendar/oauth/call`. Register the exact URI in the Google OAuth client settings. The same computed URI is used by the OAuth client for both authorization and code exchange.

Generate the encryption key with `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Keep it stable and back it up securely; changing it makes existing encrypted tokens unreadable. Install dependencies from this directory with `npm install` (includes `googleapis`).

### Local OAuth setup

1. In Google Cloud Console, create/select a project, enable Google Calendar API, and configure the OAuth consent screen. Add the Google account that will own the shared calendar as a test user if the consent screen is in testing mode.
2. Create an OAuth client ID of type **Web application**. Add `http://localhost:5000/api/calendar/oauth/call` to its authorized redirect URIs for local development.
3. Share the organizational calendar with the Google account that authorizes the integration, with permission to make changes. Set `GOOGLE_CALENDAR_ID` to `primary` for that account's primary calendar, or the calendar ID shown in Calendar settings.
4. Start the backend using `npm start`, sign in to the frontend as an active EduTechEx admin, open `/sat/admin/counseling`, and click **Connect Google Calendar**. The page calls the authorize API with its bearer token, then redirects to Google. Grant calendar access and confirm the dashboard reports Connected. Tokens remain on the backend and are encrypted in MongoDB. To reauthorize after revocation, repeat this process.

To connect without an EduTechEx student/admin login, keep the backend running in one terminal and run `node scripts/connectGoogleCalendar.js` from a second terminal in this directory. The script uses `GOOGLE_CONNECT_EMAIL` (default `developers.doc@edutechex.com`), opens Google consent in your browser, and polls MongoDB for up to three minutes. The callback is state-signed and accepts this one configured CLI identity; it does not require a bearer token. On success, the callback displays a message and the script prints the credential's connected-by and connected-at metadata, never token data.

On startup, `ADMIN_COUNSELOR_EMAIL` is created if missing and promoted to active admin. Only emails listed in the comma-separated `SUPER_ADMIN_EMAILS` (default `adityacv@edutechex.com`) that also have an active Counselor record with `isAdmin: true` can connect or reconnect Google Calendar, check its connection status, or resync bookings. Super admins see all bookings and may filter with `?counselorId=<id>`; other admins see only their own counselor bookings. Student routes require a valid student token. Existing counselor-specific availability inventory can be used by supplying `counselorId`; without it, available slots are offered every 30 minutes from 09:00 through 16:30 in the configured time zone.

Once a counseling booking is confirmed, the backend syncs it to the shared Google Calendar and creates a Meet conference when `GOOGLE_MEET_ENABLED=true`. Calendar invitations go to the student and assigned counselor. The student receives a confirmation email after the sync attempt; it includes the Join Google Meet link when available, otherwise it says the meeting link will be sent shortly. A five-minute backend retry job processes up to 20 failed or unsynced future bookings at a time. A super admin can also retry with `POST /api/admin/counseling/:bookingId/resync`, which resends the student confirmation email. Run `node scripts/checkCalendarSetup.js` from this directory to check counselor admin flags, shared credential metadata, and failed booking count without printing token contents.

### Counseling booking API examples

Use `Authorization: Bearer <token>` and `Content-Type: application/json` where there is a request body.

| Method and path | Access | Purpose |
| --- | --- | --- |
| `GET /api/calendar/oauth/authorize` | Admin | Returns an OAuth `authorizationUrl` |
| `GET /api/calendar/oauth/call` | Google redirect | Exchanges code and stores encrypted tokens |
| `GET /api/calendar/oauth/status` | Admin | Reports shared Calendar connection metadata |
| `POST /api/admin/counseling/<bookingId>/resync` | Admin | Retries Calendar sync and resends student confirmation email |
| `GET /api/counselors/<counselorId>/available-slots?date=2026-12-01` | Student | Lists the counselor's available slots |
| `POST /api/counseling/book` | Student | Creates a counseling booking; Google event and Meet link sync to the same booking record |
| `GET /api/counseling/my-bookings` | Student | Lists only the signed-in student's counseling bookings and meeting links |
| `GET /api/admin/counseling/bookings?status=confirmed` | Admin | Lists bookings (all for super admins, own counselor bookings for other admins) |

Counseling booking request:

```json
{
  "mockTestId": "01",
  "counselorId": "counselor-object-id",
  "bookingDate": "2026-12-01",
  "startTime": "10:00"
}
```

In Postman, first register/verify or log in to obtain the bearer token. Use it on slot lookup, booking, and own-bookings requests. OAuth callback is a browser redirect from Google and does not take an Authorization header; its signed state validates either the authorized super-admin flow or the configured one-time CLI connection flow.
